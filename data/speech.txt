SECTION 3: PROJECT - ATOMIC AI
------------------------------------------------------------

Interviewer:
Tell me about your most important project.

Candidate:
One of my major projects is Atomic AI. It is a multi-agent AI web application designed to provide different AI capabilities through a unified application.

The application uses React on the frontend and Node.js with Express on the backend. It also uses MongoDB and Redis. Authentication is handled using Firebase Authentication.

The system includes multiple services such as a gateway service, chat service, authentication-related functionality, and agent services. I also worked with Docker and AWS services such as ECS Fargate, ECR, Application Load Balancer, and CloudFront.

Interviewer:
Why did you use a multi-agent architecture?

Candidate:
The main reason was separation of responsibilities. Instead of putting every AI capability into one large service, different agents or services can specialize in different tasks.

For example, one capability can handle general conversation, another can handle coding-related tasks, another can perform web search, and another can work with documents or images.

This architecture can make the system easier to extend and maintain, although it also introduces additional complexity such as communication, monitoring, failure handling, and deployment.

Interviewer:
Why did you use Redis?

Candidate:
Redis is useful for fast temporary data access. In my project, it can be used for session-related data, caching, and short-lived information.

Because Redis stores data in memory, it can provide much faster access than repeatedly querying a primary database for temporary data.

Interviewer:
Why MongoDB?

Candidate:
MongoDB is a document-oriented database. It works well when application data has a flexible document structure. In an AI application, conversation and session data can contain nested or changing fields, so a document database can be convenient.

Interviewer:
How did you improve performance?

Candidate:
I used caching where appropriate, separated services, and tested the application under load. In my project testing, I used Autocannon for HTTP load testing.

The observed benchmark reached approximately 4,749.90 requests per second at peak and approximately 4,252.14 requests per second with 200 concurrent requests, with zero errors in that particular benchmark.

I would not treat a benchmark as a guarantee of production performance because real production traffic, database load, network conditions, and infrastructure configuration can be different.

Interviewer:
What is the difference between a list and a tuple in Python?

Candidate:
A list is mutable, which means its elements can be changed after creation. A tuple is immutable, so its elements cannot normally be changed after creation.

Lists are useful when data needs to change, while tuples are useful when the data should remain fixed.

Interviewer:
What is a dictionary?

Candidate:
A dictionary stores data as key-value pairs. It provides fast average-case lookup by key and is commonly used when we need to associate one piece of information with another.

Interviewer:
What is a Python virtual environment?

Candidate:
A virtual environment isolates project dependencies from the system Python installation. This prevents different projects from conflicting with each other's package versions.

Interviewer:
What is exception handling?

Candidate:
Exception handling allows a program to handle runtime errors gracefully. In Python, we commonly use try, except, else, and finally blocks.

SECTION 6: FASTAPI AND BACKEND
------------------------------------------------------------

Interviewer:
What is an API?

Candidate:
An API is an interface through which different software components communicate. In a web application, a REST API can allow a frontend to communicate with backend services using HTTP methods such as GET, POST, PUT, PATCH, and DELETE.

Interviewer:
What is the difference between authentication and authorization?

Candidate:
Authentication answers the question, "Who are you?" Authorization answers, "What are you allowed to do?"

For example, logging in with a valid username and password is authentication. Checking whether that user is allowed to delete a particular resource is authorization.

Interviewer:
What is JWT?

Candidate:
JWT stands for JSON Web Token. It is commonly used to securely represent claims between a client and server. After successful authentication, the server can issue a token that the client sends with subsequent requests.

The backend validates the token before allowing access to protected endpoints.

Interviewer:
What is middleware?

Candidate:
Middleware is code that runs during the request-response lifecycle. It can be used for tasks such as authentication checks, logging, request processing, error handling, and adding common headers.

SECTION 7: DATABASES
------------------------------------------------------------

Interviewer:
What is a primary key?

Candidate:
A primary key uniquely identifies a row in a database table. It must be unique and normally cannot be null.

Interviewer:
What is an index?

Candidate:
An index is a database structure that can improve the speed of queries on selected columns. However, indexes also require storage and can increase the cost of insert and update operations, so they should be used carefully.

Interviewer:
What is a database transaction?

Candidate:
A transaction groups multiple database operations into one logical unit. It follows the ACID principles: Atomicity, Consistency, Isolation, and Durability.

SECTION 8: AI / GENERATIVE AI
------------------------------------------------------------

Interviewer:
Why are you interested in AI Engineering?

Candidate:
I am interested in AI Engineering because it combines software engineering with modern AI capabilities. I enjoy building applications where LLMs are integrated into real products rather than only experimenting with prompts.

I am currently learning topics such as RAG, LangChain, LangGraph, embeddings, vector databases, tool calling, agents, and LLM application architecture.

Interviewer:
What is an LLM?

Candidate:
LLM stands for Large Language Model. It is a machine learning model trained on large amounts of text and other data to understand and generate language.

Examples include models designed for conversation, coding, reasoning, summarization, and other language-related tasks.

Interviewer:
What is RAG?

Candidate:
RAG stands for Retrieval-Augmented Generation.

Instead of asking an LLM to answer only from its internal model knowledge, we first retrieve relevant information from an external knowledge source and provide that information as context to the model.

A typical RAG pipeline is:

Document ingestion -> Text extraction -> Chunking -> Embeddings -> Vector storage -> Similarity search -> Retrieved context -> LLM -> Final answer.

Interviewer:
Why is RAG useful?

Candidate:
RAG is useful when an application needs to answer questions based on private, changing, or domain-specific documents.

For example, a company can store internal documentation and allow an AI assistant to retrieve relevant sections before generating an answer.

Interviewer:
What are embeddings?

Candidate:
Embeddings are numerical vector representations of text or other information. Similar meanings can be represented by vectors that are close to each other in the embedding space.

This allows us to perform semantic similarity searches.

Interviewer:
What is chunking?

Candidate:
Chunking means splitting a large document into smaller pieces before creating embeddings. Smaller chunks make retrieval more focused.

However, chunks should not be too small because important context may be lost, and they should not be too large because retrieval can become less precise.

Interviewer:
What is a vector database?

Candidate:
A vector database stores and searches vector representations efficiently. In a RAG system, it can retrieve document chunks that are semantically similar to a user's query.

Examples include systems such as FAISS, Chroma, Pinecone, Weaviate, and pgvector-based PostgreSQL setups.

SECTION 9: LANGCHAIN / LANGGRAPH
------------------------------------------------------------

Interviewer:
What is LangChain?

Candidate:
LangChain is a framework and ecosystem for building applications around language models. It provides components for model interaction, prompts, document loading, retrieval, tools, agents, and chains.

Interviewer:
What is LangGraph?

Candidate:
LangGraph is designed for building stateful, graph-based workflows and agentic applications. Instead of treating the application as only a simple linear chain, we can define nodes, state, transitions, loops, and conditional execution.

Interviewer:
What is an AI agent?

Candidate:
An AI agent is a system where an LLM can reason about a task, decide which action or tool to use, execute that action, observe the result, and continue until the task is completed.

For example, an agent could decide to search a database, call an API, calculate something, and then provide a final response.

SECTION 11: SYSTEM DESIGN
------------------------------------------------------------

Interviewer:
How would you design a URL shortener?

Candidate:
First, I would identify the main requirements.

The system needs to create a short URL, redirect users to the original URL, optionally support custom aliases and expiration, and collect analytics.

A possible architecture would contain:

Frontend
API Gateway
URL Service
Authentication Service
PostgreSQL
Redis Cache
Analytics Service

When a user opens a short URL, the system can first check Redis. If the URL is cached, it can redirect quickly. Otherwise, it can retrieve the mapping from PostgreSQL and populate the cache.

For analytics, events can be processed separately so that redirect performance is not unnecessarily affected.

Interviewer:
How would you scale it?

Candidate:
I would use stateless backend services behind a load balancer, horizontal scaling, caching, database indexing, connection pooling, and possibly asynchronous event processing.

I would also monitor latency, error rates, throughput, CPU, memory, database performance, and cache hit rates.
